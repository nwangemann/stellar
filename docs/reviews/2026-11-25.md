# Review and status, 2026-11-25

A review of the app, the docs and the development process after the real sky, details, search, find in sky, time travel and the looks were built. The changes from this pass are listed under each heading and landed together.

## Status

- **Backlog:** no step is ready. Simulator tests (task 3) wait for an OK to install Java and Maestro; the device pass (task 8) is last by design. Photo capture, a Claude-backed "ask about this star", satellite passes and a simplification decision are listed under **Later**.
- **Build:** `main` was clean and in sync with GitHub before this pass, and CI was green on its last four runs. `npm run check` passes in about 13 seconds: types, lint, formatting, 194 tests in 21 suites, and the docs check.
- **Size:** about 5,400 lines of app TypeScript in 125 files outside `src/data`, 710 lines of tests, 520 KB of bundled catalog data, 17 ADRs, 14 commits in one day.
- **Verified vs not:** the sky, details, search, find in sky, time travel, looks and night vision were checked on the iOS simulator; this pass rechecked search, find in sky, the mythology tab, time travel and the settings screen. Nothing has run on a physical phone: the camera, sensors, compass alignment, haptics, permission prompts, frame rate and battery are untested.

## The application

Strengths:

- **A clean core.** `src/core` is plain TypeScript, and ESLint enforces it. Coordinates, projection, lock-on, pose and search are pure functions with tests next to them.
- **Correctness with evidence.** Sun, Moon and planet positions are tested against JPL Horizons for two sites; the night palette is tested for any green or blue.
- **Performance by design.** The UI thread holds the stars once; a refresh sends one rotation. The canvas redraws on the UI thread without React renders while the phone moves.
- **Data provenance.** Every catalog records its source, version and licence; restrictive cultures were excluded; stories link fixed revisions.
- **Hygiene.** Strict TypeScript with `noUncheckedIndexedAccess`, clean lint and format, no TODOs, no `any`, no suppressed lint rules, no stray `console` calls in the app.

Gaps and risks:

- **No phone verification.** The headline experience, pointing a phone at the sky, depends on sensors, true north and the camera's field of view, none of which has been tried on a phone. This is the largest risk.
- **Layers is a placeholder.** The third mode shows bright stars with no layers. A reviewer opening it sees an unfinished mode. Fixed: it is now hidden from the mode strip until it has a real layer.
- **Scope of looks.** Four looks multiply the checks for every new control (ADR 14). Starship and Needlepoint make strong screenshots; Glass & chrome depends on iOS 26 and is the hardest to keep right.
- **Translucent cards over a busy sky.** Constellation lines show through the info card and can compete with its text. Fine on the simulator's plain backdrop; judge it over the camera.
- **Duplicate title.** The constellation screen shows the name in the header and again as the first card's title.
- **iPad.** `supportsTablet` is on, but sensor pose assumes portrait (ADR 16). Turning it off would remove an untested surface.

Fixed in this pass:

- The app shipped the Expo template icon. It now has its own: the reticle locked on to a figure, in the app's colours. Android uses the same icon instead of the template adaptive icon; the unused splash image is gone.
- Settings switches that were off had no outline in the Default and Needlepoint looks, so "Night vision" read as a label. An off switch now keeps an outline (Default) or the quiet button surface (other looks). Checked on the simulator in Default and Starship; Glass & chrome and Needlepoint were not rechecked.
- The Default look's subtitle read "The original Stellar"; it now describes the look.

## Process

The work followed one loop: a backlog of session-sized steps, one step per session, built and checked by the agent and recorded in the handoff ([ai-workflow.md](../ai-workflow.md)).

What worked:

- **Written state over chat history.** The backlog, handoff and system docs let each session start cold.
- **Rules learned once.** A frozen sky caused by a shared value read only in a nested helper became a gotcha in the `stellar-dev` skill; the status bar fight in night vision became ADR 12.
- **Explore, then reduce.** The details transition was built three ways behind a temporary setting and one was kept; the alien visitor was built and removed.
- **Device checks last.** Everything that needs a phone collects in task 8 and never blocked other work.
- **Gates.** Husky and commitlint ran from the first commits and CI from the eighth; every recorded CI run passed.

What cost time or needs attention:

- **Coarse commits.** Several commits bundle three or four features ("add sensors, time travel, search and find in sky"). History reads as milestones rather than steps.
- **Stale snapshots.** The handoff drifted (test count, phase table) because it is updated only when state changes. A review pass like this one catches it; a line in the session routine to update the count would too.
- **Blocked backlog.** With task 3 waiting on an install decision and task 8 deliberately last, there is no ready step. The next feature work has to come from **Later**.

## Recommendations

In order of value for a portfolio reader:

1. **Build satellite passes** as the first layer, then show Layers again. It is hidden for now.
2. **Set the GitHub description and topics** (for example `expo`, `react-native`, `skia`, `astronomy`, `augmented-reality`, `typescript`).
3. **Start task 8 on a phone**: sensors, field of view and the camera first, since they are the core of the experience. Then tag `v0.1.0`.
4. **Decide on task 3** (Maestro): one command that proves the main flow would back the simulator claims with a repeatable test.
5. **Trim the looks** if they slow feature work, and remove the duplicate title on detail screens.
